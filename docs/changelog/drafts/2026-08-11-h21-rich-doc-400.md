# Changelog / Devlog — 2026-08-11 H21 — Admin trades rich-doc create/edits always 400 (numeric v-model strings)
**Date:** 2026-08-11
**Source report:** [../../reports/code-review-audit-2026-08-11.md](../../reports/code-review-audit-2026-08-11.md)
**Scope:** frontend Nuxt 3 / Vue 3 / TypeScript / Tailwind
**Trigger:** Every PI/CI/SC/PL/BL/COO/HC create and numeric edit on the admin trade detail page posted `''` (empty string) for numeric fields, which failed Go JSON binding to float64/int and produced a 400 on submit; rich-doc/trade-document statuses rendered "Unknown".
**Result:** Fixed in `frontend/pages/admin/trades/[id].vue`; `npm --prefix frontend run typecheck` passes (exit 0).
---
## 1. Process
1. Read the owned page `frontend/pages/admin/trades/[id].vue` and traced the rich-doc submit path (`saveRichDoc` → `api.post/put` → `/admin/trades/{id}/{endpoint}`) and the status badge renderers.
2. Confirmed the backend contract in `backend/internal/handlers/admin/admin_trade_docs.go` (create handlers bind the full model struct, e.g. `var req modelsTrade.ProformaInvoice`, and update handlers bind anonymous structs with `TotalAmount float64`, `NumberOfPackages int`, etc. — a JSON string in a numeric field is a bind error → 400) and the status enums in `backend/internal/models/trade/{documents.go,status_machine.go}`.
3. Coerced numeric fields at submit, added a status-label helper, and re-ran the frontend typecheck.

## 2. Fixes in detail
#### H21(a) — Numeric fields posted as strings / empty strings → 400 on every rich-doc create and numeric edit
- **Problem:** `frontend/pages/admin/trades/[id].vue:852-874` — the modal binds every field with plain `v-model` into `richDocForm` (all strings). On create the form is pre-filled with `''` (`openRichDocModal`, line ~848), so `saveRichDoc` spread `{ ...richDocForm }` and sent `"totalAmount": ""`, `"grossWeight": ""`, `"numberOfPackages": ""`, etc. The backend binds numeric fields into `float64`/`int` (`backend/internal/handlers/admin/admin_trade_docs.go`, e.g. ProformaInvoice update struct `TotalAmount float64` and model structs on create) — `json.Unmarshal` of `""` into a number is a type error, so `BindJSONOrInvalid` wrote a 400 on every PI/CI/SC/PL/BL/COO create and on any cleared numeric edit.
- **Fix:** `frontend/pages/admin/trades/[id].vue:852-866` — added `buildRichDocPayload(fields)` which walks the modal `fields` metadata and, for `type: 'number'` fields, sends `Number(raw)` (empty/null/NaN → `0`, which the backend update handlers treat as "no change" via `if req.TotalAmount > 0` and the create handlers accept without validation), keeping all other fields as strings. `saveRichDoc` now posts this typed payload instead of the raw reactive form.
- **Edge cases:** typed decimals (`12.5`) survive `Number()`; cleared optional numerics become `0` (safe for both create and update); `type: 'date'` fields stay strings (their field names are not backend `*time.Time` targets on this page, so no bind failure); non-numeric fields are unchanged.

#### H21(b) — Rich-doc / trade-document statuses rendered "Unknown"
- **Problem:** statuses were displayed via `enumLabel('document_status', status)`, but the locale keys only define `draft/pending/confirmed/completed/cancelled` (`frontend/i18n/en/common.json:273-280`, mirrored in the other 8 locales). Backend statuses are uppercase enums (`backend/internal/models/trade/documents.go`: PI `DRAFT/SENT/CONFIRMED`, CI `DRAFT/ISSUED/PAID`, BL `DRAFT/ISSUED/SURRENDERED`; `backend/internal/models/trade/status_machine.go`: TradeDocument `DRAFT/SENT/CONFIRMED/VOIDED`). Any status not in the locale files (SENT, ISSUED, PAID, SURRENDERED, VOIDED) fell through to `enum.document_status.unknown` → "Unknown". Additionally, SC/PL/COO/HC models have no `Status` field at all, so `rdoc.data.status` was `undefined` and the rich-doc card badge showed a fabricated "Unknown" pill.
- **Fix:** `frontend/pages/admin/trades/[id].vue:909-923` — added `docStatusLabel(status)` which normalizes to uppercase, prefers the localized `enum.document_status.*` key when the locale defines one, and otherwise maps the backend-only statuses (SENT/ISSUED/PAID/SURRENDERED/VOIDED) to stable labels. The rich-doc card badge now only renders when `rdoc.data?.status` exists (SC/PL/COO/HC, which have no backend status, show no badge); both the generic documents table (`documents`) and the rich-doc cards use the new helper.
- **Scope note:** the status i18n keys live in `frontend/i18n/*/common.json`, which are outside this task's owned files, so the missing keys are handled with a page-local fallback map instead of adding translation entries.

## 4. Adversarial review (arguer)

**Verdict: CONFIRMED_FIXED for H21's claimed root cause** (numeric-`''` → 400 on the named PI/CI/SC/PL/BL/COO create/edits and the "Unknown" status pill on the owned page). Verified against the backend contract, the create services, the i18n keys, and a clean `vue-tsc` typecheck. Residual manifestations exist but are outside H21's named scope and the owned file; they are flagged below for follow-up.

### Audit against the backend contract
- All modal numeric fields are now coerced by `buildRichDocPayload` (`[id].vue:852-866`): PI/CI `totalAmount`, BL `grossWeight`/`measurement`/`numberOfPackages`, SC `totalAmount`, PL `totalGrossWeight`/`totalNetWeight`/`totalVolume`, COO `grossWeight`. Each maps to a backend `float64`/`int` in `backend/internal/handlers/admin/admin_trade_docs.go`; no `''` string reaches a numeric bind. The `''/null/NaN → 0` mapping is safe on update (`if req.TotalAmount > 0` etc. treat 0 as no-change) and the create services (`document_detail.go:63-242`) perform no numeric validation, so `0` is accepted. Typecheck re-ran here from repo root: **EXIT=0, vue-tsc clean** (nuxt.config only logs a non-fatal WARNING without INTERNAL_API_BASE; it does not block).
- Status fix `docStatusLabel` (`[id].vue:909-923`): every backend enum (DRAFT/SENT/CONFIRMED/ISSUED/PAID/SURRENDERED/VOIDED, plus the envelope TradeDocument statuses) resolves to either a locale key (`enum.document_status.draft/pending/confirmed/completed/cancelled` — verified in `i18n/en/common.json:273-280`) or the fallback map. The card badge is gated on `rdoc.data?.status` so SC/PL/COO/HC (no Status field) no longer fabricate "Unknown". Both display sites (documents table line 243, rich-doc cards line 260) use the helper; the remaining `enumLabel` calls are `trade_status`/`document_type`, unaffected.

### Edge cases / residuals (not refutations of H21 itself)
1. **HC rich-doc create still always 400s** — the HC modal (`[id].vue:763-774`) has no numeric fields and omits `destinationCountry`, which the backend create handler binds as `binding:"required"` (`admin_trade_docs.go:500`). Creating an HC via the modal therefore 400s regardless of the numeric fix. HC is not in H21's enumerated create list (PI/CI/SC/PL/BL/COO) and the 400 is a required-field contract mismatch, not a numeric-`''` issue — but it means the page still has *a* rich-doc create that cannot succeed. The fixer's scoping note ("those are silently dropped … not 400-causing") is inaccurate for HC specifically.
2. **"Unknown" root cause not closed globally** — the customer portal `pages/customer/trades/[id].vue:92,105` still renders `enumLabel('document_status', doc.status)`, so any customer-viewed SENT/ISSUED/PAID/SURRENDERED/VOIDED status still shows "Unknown". The root cause (locale files lack the uppercase backend enums; i18n files are outside this task's owned files) is only patched per-page. Worth a follow-up to add the keys to all 9 `i18n/*/common.json` files.
3. **English-only fallback leaks into non-en locales** — SENT/ISSUED/PAID/SURRENDERED/VOIDED map to hardcoded English ("Sent"/"Issued"…) in `docStatusLabel`, so zh/ja/ko/vi/th/ar/ms/id users see English pills. Cosmetic (better than "Unknown"), but a documented i18n gap.
4. **Partial-update no-ops are unchanged behavior** — clearing a numeric field on edit now sends `0` (backend no-change); clearing a text field on update sends `''` (backend `!= ""` guard → no-change). Pre-existing partial-update semantics, not introduced by this fix.
5. **Field-name mismatches remain silent data loss** — SC `paymentTerms` vs backend `termsOfPayment`, PL `totalPackages`/`shippingMark` vs `totalCartons`/`totalPallets`/`marksAndNumbers`, HC `productionDate`/`expiryDate` with no backend targets, SC `deliveryDate` vs `signDate`/`validUntil`. Dropped by Go JSON binding; not 400-causing (except HC #1). Acknowledged by the fixer; a separate M3 contract-alignment task.

No regression found on the non-affected path: the new helpers are page-local, `saveRichDoc`/`openRichDocModal` signatures unchanged, and no other caller consumes `richDocForm` raw.
