## 2. Fixes in detail

#### G29(a) — HITL wrapper: completion path for read-only tools
- **Problem:** `backend/internal/pkg/eino/tool/review_edit.go:70-76` — the `!wasInterrupted` branch unconditionally called `tool.StatefulInterrupt(...)` for every wrapped tool. All three wrapped tools are read-only/informational (`track_shipment`, `translate_content`, `validate_lc_documents`), so every call interrupted the agent. The runner/SSE layer (`handlers/system/sse_handler.go`) only surfaces the interrupt and has no resume route, so the tools could never complete and the live 17track carrier provider behind `track_shipment` was unreachable dead code.
- **Fix:** Added a configurable `ReviewPolicyFunc` (field `InvokableReviewEditTool.RequiresReview`) with a default policy that exempts the three read-only tools (`reviewExemptTools` set). On first invocation `InvokableRun` now executes exempt tools directly and returns their real result instead of interrupting (`review_edit.go`). The HITL interrupt flow is preserved for any tool that is not exempt or that a caller forces through review via `RequiresReview`. Regression tests: `tool/review_edit_test.go` — `track_shipment` and `translate_content` complete through the wrapper (would fail pre-fix with an interrupt error), a non-exempt tool still interrupts, and a custom policy can force an exempt tool back through the gate.

#### G29(b) — `Client.Generate` leaks raw tool output
- **Problem:** `backend/internal/pkg/eino/client.go` (Generate loop) accumulated `msg.Content` / `chunk.Content` for every message, including `schema.Tool`-role messages that carry raw tool results (JSON from persister / tracker / translation). Those blobs were concatenated into the final user-facing answer.
- **Fix round 1:** Extracted `accumulateMessageOutput(final, *adk.MessageVariant)` which skips `Role == schema.Tool` messages and tool-result stream chunks; `Generate` uses it (same error/log semantics). Regression tests in `client_test.go` cover plain tool message, assistant message, empty assistant message, mixed tool+assistant stream chunks, and nil variant.
- **Fix round 2 (refutation — empty reply regression):** dropping *every* Tool-role message also dropped the legitimate terminal result of the `ReturnDirectly` tool `submit_quotation_for_human_review` (`agent.go:114-117`). In Eino v0.7.36 the ReturnDirectly final event is a `Role==Tool` message carrying the user-facing tool result (`adk/chatmodel.go` `createToolResultSender` stores it; `onToolsNodeEnd` → `sendReturnDirectlyToolEvent` emits it last; `adk/react.go` routes to END right after). `Generate` now tracks the trailing `MessageOutput` and re-appends it after the stream ends via the new helper `appendTerminalToolResult` (`client.go`); `accumulateMessageOutput` still filters intermediate tool output. Because a non-ReturnDirectly tool result is never the trailing event (the model always re-runs after it), the helper cannot leak raw tool output. End-to-end regression: `TestGenerate_ReturnDirectlyTerminalResultPreserved` builds a minimal `ChatModelAgent` with a fake `ToolCallingChatModel` that issues one `submit_quotation_for_human_review` call (ReturnDirectly), attaches it to `Client{agent:...}`, and asserts `Generate` returns the tool's `pending_human_review` summary — on the pre-fix path this returns `""` (demonstrated: `got reply ""`). `TestAppendTerminalToolResult` covers pure-terminal, mixed assistant+terminal, non-tool trailing, empty-content, nil, trailing-stream-variant, and separator cases.
- **Fix round 3 (arguer edge case — cosmetic concatenation):** `appendTerminalToolResult` joined the appended terminal result directly to accumulated assistant text, so a reply whose accumulated text did not end in whitespace read `…discount hint 5.0%)Queued quotation review: …`. `client.go` now inserts a `\n\n` separator only when `final` is non-empty and does not already end in `" "` or `"\n"`; the pure-terminal path (empty `final`) is unchanged. `TestAppendTerminalToolResult` gained the non-whitespace-terminated case (asserts `Final discount hint 5.0%\n\nQueued for review`, FAILS pre-fix with the merged `Final discount hint 5.0%Queued for review` — demonstrated), a newline-terminated no-double-separator case, and a trailing-Tool-*stream* variant case (Message nil → ignored). I also hardened the invariant documentation against the arguer's "tool-error routed to END" scenario: `compose/tool_node.go` `ToolsNode.Invoke` returns `fmt.Errorf("failed to invoke tool...")` for a failing tool and never emits a Tool message with the error string, so a tool error fails the graph run and `Generate` returns early on `event.Err` before `appendTerminalToolResult` runs; and the only agents attached to a `Client` (`cmd/api/main.go:140`, `internal/handlers/admin/handler.go:64`, both `h.System.TradeAgent()`) are `ChatModelAgent` react loops, where the trailing-Tool-event ⟺ ReturnDirectly invariant holds by construction.

#### G29(c) — Document-number generation collisions (NOT in owned files; re-confirmed live round 3)
- **Problem:** `backend/internal/pkg/eino/graph/pipeline.go:206` (`NewBatchDocSeq`) derives `seq := int(now.UnixMilli() % 100000)`. Two generation batches in the same millisecond (concurrent SSE connections / parallel agent runs), or any two batches exactly 100,000 ms apart on the same day (the residue wraps every 100 s, each residue recurs ~864 times/day → birthday collisions near-certain at a few hundred batches/day), share the same `Date`+`Seq`, and `TradeDocument.DocNumber` has `uniqueIndex` (`models/trade/trade.go:69`) → duplicate-number rows / unique-violation on `AddDocument`, with the error only appended to `state.Errors` (status becomes `partial`).
- **Status:** **Out of owned-file scope** (tracked as task G29(c)). Lives in `internal/pkg/eino/graph/pipeline.go`, concurrently modified this session by the pipeline owner. Recommended patch: make `NewBatchDocSeq` collision-resistant — per-process monotonic `atomic` counter (or random suffix) appended to the batch identity, keeping the shared-batch invariant that every doc in one batch shares the number suffix; a uniqueness regression test belongs in `internal/pkg/eino/graph/pipeline_test.go` (the existing `TestNewBatchDocSeq` asserts the modulo behavior, not uniqueness, and would not catch the collision).

#### G29(d) — CI `pol` field filled with an Incoterms string (NOT in owned files; re-confirmed live round 3)
- **Problem:** `backend/internal/pkg/eino/graph/pipeline.go:251` — the Commercial Invoice template writes `"pol": %q` populated with `input.Incoterms` (rendered at `:253`), i.e. the port-of-loading field is filled with a term like `"FOB Shanghai"` (also the default, `pipeline.go:87`) rather than an actual port. Downstream LC validation / customs-styled documents read a nonsense "port"; the term is rendered into `pol` even when a real port is available in the input.
- **Status:** **Out of owned-file scope** (tracked as task G29(d)). Same file as (c). Recommended patch (for the pipeline.go owner): add a dedicated `PortOfLoading` (and optionally `PortOfDestination`) field to `DocGenerationInput`, thread it through `PrepareContext` → `generateDocument`, and render `"pol"` from the port value while keeping `"incoterms"` on the Incoterms term.

#### G29 latent — `RequiresReview` can re-route an exempt tool back to the dead-end interrupt path
- **Problem (arguer edge case):** `RequiresReview` is a public override; a caller that sets it on a wrapped tool re-routes that tool to the interrupt path, which still has no resume route in the SSE layer (`handlers/system/sse_handler.go`) — a dead-end for any future state-changing wrapped tool.
- **Response:** Documented limitation of the extension point, not reachable with current wiring: the three wrapped tools are read-only and exempt by default, and no caller sets `RequiresReview` to force a state-changing tool (the only setter is the `_CustomPolicyForcesReview` test). Closing the SSE resume gap belongs to the SSE-layer owner (`handlers/system/sse_handler.go`), outside owned-file scope. Re-affirmed round 3.
