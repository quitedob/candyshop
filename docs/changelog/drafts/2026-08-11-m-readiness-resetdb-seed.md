## 2. Fixes in detail
#### G27-a — `/ready` returns 200 with DB down
- **Problem:** `backend/internal/api/router.go:198-208` — the `ai_agent_not_ready` branch returned `200 ready` (with a warning) *before* the DB failure check ran. With the optional AI agent uninitialized, `/ready` reported healthy even when the hard DB dependency was unreachable, hiding the outage from LB/health checks.
- **Fix:** Reordered `router.go:184-223` so the DB failure list is checked first (`503 not_ready` + `failures`), and only then does a non-ready AI agent yield the degraded `200` with the `ai_agent_not_ready` warning. The DB remains a hard dependency; the agent stays optional.
#### G27-b — `make reset-db` hangs
- **Problem:** `Makefile:120-126` — `reset-db` invoked `@make migrate`, and the `migrate` target (`Makefile:100-102`) runs `go run cmd/api/main.go`, i.e. it *starts the API server* and blocks forever, so `reset-db` hung after recreating Postgres.
- **Fix:** `Makefile:120-127` — `reset-db` now runs the seed CLI directly (`cd backend && go run cmd/seed/main.go -all`). The seed CLI runs `database.AutoMigrate` first (migration), then essential/business/demo seeding — no server is started. Added a comment explaining why `make migrate` must not be called here.
#### G27-c — product translation seed reverts admin edits
- **Problem:** `backend/internal/database/seed.go:850-851` (and the all-products loop at ~877) — `seedProductTranslations` merged the zh seed map with `p.Translations[locale][k] = v` unconditionally and then ran `syncProductScalarsFromZh` which re-mapped zh onto the `Name/Summary/Description/...` scalar columns on every run. Re-seeding (`make seed`, `AUTO_SEED_DATA=true` on restart, `reset-db`) silently reverted admin-edited product translations and scalar fields to the seed defaults (M4).
- **Fix:** `seed.go:850-871` and `seed.go:877-891` — (1) the zh translation merge is now fill-only: a key is only set when it is empty/whitespace, so existing (admin-edited) translations are preserved; (2) an `alreadyLocalized` guard (product already carries a non-empty `zh.name`) suppresses `syncProductScalarsFromZh`, so the zh→scalar mapping only happens on the initial seed run. Mirrors the H14 `base_price = 0 OR base_price IS NULL` philosophy (only set when unset). Fresh seeds still populate zh + Chinese scalar names (pinned by test).
- **Test:** `backend/internal/database/seed_product_translations_test.go` — `TestSeedProductTranslations_KeepsAdminEdits` seeds a product with an admin-customized zh translation + scalar Name, re-runs `seedProductTranslations`, and asserts the edits survive; verified it FAILS on the pre-fix path (`got "四维水果软糖" want "管理员定制软糖"`). `TestSeedProductTranslations_FreshSeedFillsLocalizedFields` pins that fresh seeds still fill zh and map it to the scalar.
#### G27-c (refutation round 2) — runtime product path no longer routes through the unguarded legacy sync
- **Problem:** the exported `SeedProductTranslations` wrapper called `seedProductMissingLocales` (`seed_catalog_i18n.go:201-252`), which ran `syncProductScalarsFromZh` unconditionally at lines 218 and 235 for every product and `repairProductZhCopiedFromEN` at line 217 — defeating the `alreadyLocalized` guard on the exact path `cmd/api/main.go:112` calls on `AUTO_SEED_DATA=true`. A scalar written without touching translations (e.g. the inventory XLSX importer `UpdateProductColumns` at `admin_inventory_xlsx.go:537`) diverged from `zh.name`, and the next restart reverted it; `repairProductZhCopiedFromEN` also deleted the whole zh map whenever `en.name == zh.name`.
- **Fix:** `seed.go:1008-1020` — the wrapper now calls the new guarded `seedProductMissingLocalesGuarded` (`seed.go:911-964`), which fills missing non-zh/en locales from en but (a) never re-maps zh → scalar on already-localized rows and (b) never runs `repairProductZhCopiedFromEN`. Also removed the `repairProductZhCopiedFromEN` call from the owned inner all-products loop (`seed.go:879`) — the seed path never copies zh from en, so the "repair" could only delete legitimate admin-authored zh maps. Fresh-seed behavior (zh primary locale → scalars) is preserved via the `isProductLocalized` guard (`seed.go:895-901`).
#### G27-c (refutation round 2) — wrapper no longer re-overwrites categories on the AUTO_SEED path
- **Problem:** the wrapper also called `seedAllCategoryTranslations`, re-running the M3 category overwrite on every `AUTO_SEED_DATA` boot on top of the every-boot call at `cmd/api/main.go:85`.
- **Fix:** `seed.go:1002-1007` — the wrapper no longer touches categories (redundant `seedAllCategoryTranslations` call removed); category translations are seeded every boot by `SeedCategoryTranslations`. The root M3 overwrite itself (`seed_catalog_i18n.go:101-142` + the `cmd/api/main.go:85` call) is outside the owned-file set and remains a documented residual (see §3.5).
- **Test:** `seed_product_translations_test.go` — added wrapper-level regression tests driving the exported `SeedProductTranslations`: `TestSeedProductTranslationsWrapper_KeepsDivergentScalar` (divergent scalar survives a re-seed), `TestSeedProductTranslationsWrapper_FreshSeedLocalizes` (fresh seed still localizes through the wrapper), `TestSeedProductTranslationsWrapper_NoZhDataLossWhenNamesEqual` (zh map survives when `en.name == zh.name`), and `TestSeedProductMissingLocalesLegacyStillRevertsScalar` (characterizes the legacy unguarded function, keeps it reachable for `seed_catalog_i18n.go` cleanup and for the `unused` linter).
#### G27-c (refutation round 3) — category overwrite (M3): tested drop-in guard shipped, root still owned elsewhere
- **Problem:** `backend/internal/database/seed_catalog_i18n.go:101-142` — `seedAllCategoryTranslations` writes `cat.Translations[locale][k] = v` with no emptiness guard (line 115) for every seed-map key and unconditionally overwrites the scalar `cat.Name` with the zh name (lines 129-133) for all 7 seeded slugs; it is fired every boot, with or without `AUTO_SEED_DATA`, by the unconditional `database.SeedCategoryTranslations(db)` at `cmd/api/main.go:85`. An admin rename of a category zh name (or edit of any seed-map field) is silently reverted on the next plain restart. Both root-cause files are outside this task's owned set.
- **Fix:** within the owned boundary, `seed.go:966-1010` — added `isCategoryLocalized` (mirror of `isProductLocalized`) and `applyCategoryI18nSeedGuarded(cat, localeMap)`, a fill-only, alreadyLocalized-gated category merge identical in shape to the accepted product fix: translation keys are only written when empty/whitespace, the en fallback still backfills empty scalar `Name/Alias/Description`, and the zh name is only mapped onto `Name` on the initial seed run. This is the exact implementation the `seed_catalog_i18n.go` owner should wire into `seedAllCategoryTranslations` (replace the inner `if cat.Translations == nil {…}` block through the zh-overwrite with `applyCategoryI18nSeedGuarded(&cat, localeMap)` and keep the `db.Model(&cat).Updates(...)`). The `cmd/api/main.go:85` call can stay; the guarded merge makes it idempotent. This closes M3 end-to-end but requires those two files, which this task cannot edit.
- **Test:** `backend/internal/database/seed_category_i18n_test.go` — `TestApplyCategoryI18nSeedGuarded_KeepsAdminEdits` (admin zh/ko translation + scalar Name survive, missing en keys still backfilled), `TestApplyCategoryI18nSeedGuarded_FreshSeedMapsZh` (fresh seed still maps zh name onto `Name` and backfills the empty en alias fallback, preserving original semantics), and `TestSeedAllCategoryTranslations_RevertsAdminZhName` (characterization: seeds an admin-customized zh name, runs the current `seedAllCategoryTranslations`, and documents the revert to the seed default; fails once the owner fixes the file — the failing-on-fix signal).
